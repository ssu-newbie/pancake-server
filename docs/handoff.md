# PancakE 인수인계와 다음 작업

## 자료의 기준

현재 GitHub 서버 소스와 새 회귀 테스트는 직접 검토·실행했다. 이후 업로드된 `PancakE_v5_scripts (40).zip`의 Unity 소스를 대조했다. [확인 결과](client-integration.md)에 코드에서 확인한 내용과 실행 검증을 구분했다. Claude가 작성한 `HANDOFF.md`는 이전 작업에 관한 전달 기록이다. 문서의 `[확인]` 표시는 당시의 확인 상태이며, 이번 작업에서 소스와 실행 결과를 대조했다는 뜻이 아니다.

## 역할

인수인계에 따르면 사용자는 팀 리더·개발 담당으로 요구사항과 자료를 제공하고 Unity 편집, 빌드·실행, 배포와 플레이 검증을 수행했다. Claude가 C#·Python 코드를 작성했다. 이번 서버 책임 분리와 자동화 테스트·문서 정리는 GPT/Codex와 협업한 변경이다.

## 현재 상태

| 영역 | 확보한 근거 | 다음 단계 |
| --- | --- | --- |
| FastAPI 서버 | GitHub 소스와 로컬 회귀 테스트 | 초안 PR 검토, 운영 환경과 대조 |
| Unity → 서버 요청 | `SurveyClient.cs`와 `ContentDatabase.cs`에서 주장 ID·필드 확인 | Unity 직렬화 및 실제 연결 검증 |
| 서버 연결 실패 시 대체 데이터 | `GameManager.ResetRun`에서 구성 우선순위 확인 | 실제 타임아웃·누락 응답 재현 |
| 내장 설문 데이터 | 실제 80개 행, 각 112자리 확인 | 문항 변경 시 ID·순서 호환성 유지 |
| 과거 성능·시뮬레이션 | 실행 원본 자료 없음 | 수치의 포트폴리오 기재 보류 |

## 확보한 파일과 추가 실행 환경

`PancakE_v5_scripts (40).zip`의 런타임·Editor 스크립트를 확보했다. 같은 ZIP의 서버는 기존 GitHub 기준 소스와 일치한다.

다음은 전체 Unity 프로젝트의 실행 환경이 필요하다. `Packages/manifest.json`, `Packages/packages-lock.json`, `ProjectSettings/ProjectVersion.txt`, 사용하는 씬과 해당 `.meta`가 있으면 정확한 프로젝트 조합을 확인할 수 있다. 바이너리 모델·폰트·음원의 공개 범위는 별도로 정한다.

## 우선순위

1. 소스에서 확인한 계약을 Unity 실행에서도 검증
2. 게임 진행 상태와 UI·씬 이름 의존 관계 기록
3. 핵심 플레이 흐름의 실행 기준 확보 후 작은 단위로 책임 분리
4. 이전·이후 동작 근거를 연결한 포트폴리오 사례 작성
